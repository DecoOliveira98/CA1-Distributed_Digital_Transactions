## 1. Delegation – Deciding whether and when to use AI

I used AI only as a supporting tool, within the uses allowed by the lecturer:

- **Project outline:** drafting a step-by-step outline of the project phases (setup, research), which I then adapted to my own timeline in `docs/project_plan.ipynb`.
- **Grammar and clarity:** reviewing the grammar and clarity of my written content.
- **Code comments:** improving the wording of comments I had written in the code, so they explain each part more clearly. The code itself was not changed by AI.
- **Commit messages:** suggesting clear, consistent wording for Git commit messages describing changes I had made.
- **README structure:** suggesting how to organise the sections of the `README.md`.

AI added value by saving time on planning and on the clarity of my writing. I decided **not** to use AI for the technical implementation (the Solidity contract, the Python and shell scripts), the research analysis, the testing in Remix and Ganache, or the design decisions, because these are the parts that assess the learning outcomes of the module.

---

## 2. Description – How I prompted the AI

I described each task with its goal and context, for example by giving the assessment brief and asking for an outline of the phases, or by pasting my own comment or paragraph and asking for a grammar and clarity review only, without changing the meaning. When the first output was too long or went beyond what I asked (for example, adding content instead of only correcting it), I refined the prompt to limit the scope.


---

## 3. Discernment – Evaluating what the AI produced

I reviewed every AI output before using it. From the outline, I accepted the overall phase structure but modified the dates, scope and checklists to fit my own plan, and removed items the brief marked as optional. For grammar and comments, I accepted corrections that kept my meaning and rejected changes that made the text longer or less accurate. Commit message suggestions were checked against the actual changes in each commit and edited where they did not match. For the README, I kept the suggested section order but wrote and verified the content myself. Overall, the outputs were relevant and accurate for writing tasks, but needed editing to stay concise and true to my work.
